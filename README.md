# **LSM-Tree Storage Engine**

Встраиваемое Key-Value хранилище на базе LSM-дерева (Log-Structured Merge-tree) с сетевым интерфейсом. Реализована классическая схема «WAL → memtable → неизменяемые SSTable → компакция».

## **Архитектурные особенности**

* **LSM-структура**: запись идёт в журнал и в упорядоченную структуру в памяти, на диск данные попадают пачками в виде неизменяемых SSTable-файлов.
* **Гарантии Durability**: каждая запись попадает в WAL и подтверждается только после `fdatasync`. Журнал усекается лишь после того, как memtable гарантированно записана в SSTable и файл открыт на чтение, поэтому краш на любом промежуточном шаге не теряет подтверждённых данных.
* **Целостность**: каждая запись WAL защищена CRC32, который проверяется при восстановлении. Оборванный последним крахом хвост журнала отбрасывается. SSTable содержит сигнатуру с версией формата и футер с контрольной сигнатурой; все смещения и длины валидируются при открытии.
* **Эффективное чтение**: фильтр Блума (~10 бит на ключ, 4 хэша) отсекает отсутствующие ключи, индекс каждого SSTable загружается в память при открытии, поиск по нему бинарный. Данные читаются через `pread` по удерживаемому дескриптору — файл не переоткрывается на каждый запрос.
* **Фоновые процессы**: major compaction сливает все SSTable в один и физически удаляет tombstone'ы. Файлы, созданные флашем во время компакции, сохраняются и не теряются.
* **Конкурентность**: `std::shared_mutex` защищает memtable, WAL и список SSTable. Параллельные чтения не блокируют друг друга, писатели получают эксклюзивный доступ. Компакция работает со снапшотом списка файлов вне блокировки и подменяет список атомарно; поток компакции присоединяется в деструкторе, а не отсоединяется.

## **Технический стек**

* **Язык**: C++20
* **Сборка**: CMake 3.20+
* **Зависимости**: ZLIB (CRC32), Threads (POSIX threads)
* **Сетевой слой**: нативные TCP-сокеты, строчный текстовый протокол с keep-alive

## **Формат данных SSTable**

Файл `.sst` состоит из четырёх секций:

1. **Сигнатура (8 байт)**: `LSMSST` + версия формата.
2. **Data Blocks**: последовательные записи `[K_SIZE:u32][KEY][FLAGS:u8][V_SIZE:u32][VALUE]`. Бит 0 в `FLAGS` — признак удаления (tombstone).
3. **Bloom Filter**: битовая маска, размер хранится в футере.
4. **Index Block**: полный индекс `[K_SIZE:u32][KEY][OFFSET:u64]`, отсортированный по ключу.
5. **Footer (40 байт)**: `index_offset`, `index_count`, `bloom_offset`, `bloom_bytes` и та же сигнатура.

Все целые пишутся в little-endian, поэтому файл переносим между машинами. Файл создаётся во временном пути, fsync-ается и атомарно переименовывается, так что частично записанный SSTable никогда не виден читателям.

## **Формат записи WAL**

`[CRC32:u32][K_SIZE:u32][V_SIZE:u32][FLAGS:u8][KEY][VALUE]` — контрольная сумма считается по всей записи после самого поля CRC.

## **Сборка и запуск**

### **Компиляция**
```
cmake -S . -B build
cmake --build build -j$(nproc)
```

### **Тесты**
```
ctest --test-dir build --output-on-failure
```

Набор покрывает round-trip через flush, tombstone'ы, восстановление после аварийного завершения, оборванный хвост WAL, компакцию (в том числе переживающую перезапуск), крупные значения, конкурентный доступ и отказ читать файл чужого формата. Тесты проходят чисто под AddressSanitizer, UndefinedBehaviorSanitizer и ThreadSanitizer.

### **Запуск сервера**

Сервер слушает порт 6379 и хранит данные в `./data`.
```
./build/lsm_main
```

### **Использование клиента**
```
./build/lsm_client
lsm-db> SET user:100 Full Name
lsm-db> GET user:100
lsm-db> DEL user:100
lsm-db> FLUSH
lsm-db> COMPACT
lsm-db> STATS
lsm-db> BENCHMARK 10000
```

Клиент держит одно соединение на всю сессию, поэтому бенчмарк измеряет хранилище, а не установку TCP-сессий.

## **Производительность и её границы**

Пропускная способность записи упирается в `fdatasync` — примерно одна durable-запись на оборот носителя (порядка 3 тыс. оп/сек на одном соединении в контейнере). Это осознанный размен: без синхронизации подтверждённая запись теряется при отключении питания. Групповой коммит нескольких записей в один `fdatasync` — очевидное следующее улучшение.

Чтение отсутствующего ключа обычно не доходит до диска вовсе: его отсекает фильтр Блума, а индекс и так уже в памяти.

## **Ограничения текущей версии**

* Компакция только major: сливает все файлы разом, поэтому её стоимость растёт вместе с объёмом базы.
* Индекс полный, а не разреженный: он целиком держится в памяти, объём линеен по числу ключей.
* Merge при компакции материализует все данные в памяти.
* Сервер не имеет аутентификации и слушает все интерфейсы — не выставляйте порт наружу.
* Значения не могут содержать перевод строки: протокол строчный.
